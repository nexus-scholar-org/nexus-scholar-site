Released on 2026-11-10, on top of [1.1.0b5](../1-1-0b5/). This is the current
beta. Install or upgrade:

```bash
uv tool install --force "nexus-scholar>=1.1.0b6"
nexus-scholar --version   # nexus-scholar 1.1.0b6
```

Do not install with `--prerelease allow` (see [1.1.0b4](../1-1-0b4/)).

## What changed for you

- **Search databases from the browser.** Discovery is now in the primary
  navigation (Workspaces · Discovery · Screening). The steps are an entry page,
  then Plan, Recall, Harvest, Import, Duplicates, Report and Hand-off. The
  screens are in English, French and Arabic. See
  [Discovery](../../flow/discovery/).
  - **Plan** shows, per database, the exact query string that will be sent,
    the request, notes and what the database cannot express. It is a dry run;
    nothing is sent.
  - **Recall** checks that papers you already know are found. It only checks:
    it never rewrites the query and never swaps a record. Each check is saved
    in the workspace.
  - **Harvest** runs the search and shows each database as it finishes. You can
    set a cap for this run and add a note; both are recorded. Cancel keeps what
    was fetched and archives the run as partial; nothing is built from it. A
    capped database always reads "at least N".
  - **Import** is the existing import screen, with a link back to Discovery.
  - **Duplicates** shows counts per rule (identifier, exact title, close
    title).
  - **Report** is the PRISMA-S identification per database, with a methods
    paragraph you mark as reviewed.
  - **Hand-off** freezes the corpus and opens the screening home.
- **A browser harvest does not freeze the corpus; the hand-off does.** A
  browser run stops before the corpus snapshot. You accept it on the Hand-off
  screen, which builds the same snapshot the terminal `run` builds from the
  same records. The terminal `run` is unchanged and still accepts at the end.
- **A corpus is a harvest or imported exports, not both, for now.** After a
  search run, adding an export is refused with `VERIFIED_EXISTS`, and the
  import screen says why.
- **Import reports the lines it could not read.** The RIS and `.nbib`
  importers list rejected lines with `IMPORT_NO_TITLE`, `IMPORT_BAD_TAG` or
  `IMPORT_BAD_YEAR`. A record without a title is still imported, so no record
  id moves.
- **Deduplication records why records merged.** Each merge keeps the rule it
  was made by. Record ids do not change.

## Existing workspaces

Nothing in an existing workspace changes. Workspaces created by a terminal
`run` stay accepted.

## For anyone calling the local API or the tools

New routes under `/api/v1/discovery` (plan, runs, report, hand-off,
deduplication, recall, and jobs with a live event stream; one job runs per
workspace). A failed database carries a typed code beside its text:
`PROVIDER_RATE_LIMITED`, `PROVIDER_TIMEOUT`, `PROVIDER_UNAVAILABLE` or
`PROVIDER_REFUSED`. New refusal codes include `DISCOVERY_JOB_ACTIVE`,
`PROVIDER_UNKNOWN`, `DEDUP_NOT_RUN` and `PROTOCOL_CHANGED_SINCE_RUN`. New
journal events: `DISCOVERY_RECALL_CHECK`, `METHODS_TEXT_REVIEWED` and
`PIPELINE_RUN_PAUSED_FOR_CORPUS_ACCEPT`.

## Known limits

The limits of [1.1.0b5](../1-1-0b5/) and the [known limits page](../../known-limits/)
still apply, except that Discovery now has screens. Also:

- **OpenAlex needs an API key.** OpenAlex made keys mandatory on 2026-02-13.
  Set `SCHOLAR_OPENALEX_KEY` as well as `SCHOLAR_MAILTO`. Without the key,
  OpenAlex documents that paging past the first page is refused, so its search
  stops after one page. The app still treats the key as optional. See
  [Configuration](../../configuration/).
- **PubMed abstract terms search all fields.** The query uses a field tag
  PubMed does not know. A fix is planned.
- **Default databases differ.** The browser and a plain terminal search use
  five databases; a protocol that names none uses four (no PubMed).
- **New and untested by a second person.** The Discovery screens were built
  and checked by one developer, against a simulated engine in the browser
  tests. Expect rough edges.
- **No live search was run for this release.** Every test replays recorded or
  in-memory database answers.
- **No phone access, and one reviewer.** Screening is one reviewer, title and
  abstract only.
- **Not built:** pair-by-pair review of near-duplicates, one corpus from a
  harvest plus exports, and a per-database stop. Accept is disabled on screen
  while a harvest runs, but the engine does not yet refuse it.
- **Explore and Direction (inception) still have no screens.**
- **Still parked:** synthesis, the evidence matrix, the citation graph and
  risk-of-bias trust.
